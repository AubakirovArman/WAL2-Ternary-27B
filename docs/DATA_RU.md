# Данные: подготовка, split и ограничения

Учитель в основной подготовке — Qwen3.8-27B-FP8 через существующий chat API. Мы не предполагаем, что synthetic-ответ автоматически правильный. Где можно, используются точный программный решатель, unit tests, проверка JSON/формата, допустимость параметров и контроль конечного ответа. Для математики совпадение итога проверяется отдельно от teacher-рассуждения: эвристическая review не является формальным доказательством.

Не все generated токены попадают в обучающий корпус: failed format, wrong final, retry и слишком длинные ответы отвергаются.

До сбора создаются задачные families, train/validation назначения, seed и exclusion-проверки. Поддерживается SHA содержимого и ID каждого примера, проверяется отсутствие exact совпадения между split. Для E020 train16 math families и validation4 families,1024/256 examples, отдельные 64 control исключены. Семантические близнецы не исключаются одной hash-проверкой; следующая версия должна иметь более сильный split и новый независимый набор генерационных задач.

Concurrency50 ускоряет collection за счёт batching teacher-сервера. Контролируются rate, retries, число accepted/rejected, completed splits и сроки. Максимум output tokens выбирается по сложности: длинное reasoning не следует насильно делать коротким до 2048. При тренировке длинные примеры не обрезаются скрыто; должна быть явная политика reject или выбранная допустимая длина. Loss chunk64/512 относится к памяти output head, а не к лимиту reasoning.

Публичный снимок включает генераторы/аудит/подготовку и числовые evidence. Он **не включает полный смешанный corpus** и teacher caches. Источники имеют разные лицензии (отдельные public datasets, задачи, code); перед выпуском нужны source/license ledger, допустимость перераспространения teacher-ответов и prompts, dedup и contamination audit. Лицензия Apache-2.0 на код не перелицензирует чужие данные.

Репозиторий позволяет изучить реализованный процесс, но точное воспроизведение исходных моделей E004→E020 из одного Git checkout невозможно без сохранённых корпусов, cache и parent masters. Их отсутствие явно обозначено; повторное использование генераторов создаёт новый воспроизводимый эксперимент с собственным dataset hash, а не тот же historical run.
